# DOBO CAD Kernel

# Surface Engine API Specification

**Version:** 2.0

---

# 1. Purpose

This document defines the public API of the Surface Engine.

The Surface Engine is responsible for adapting and positioning two-dimensional geometry onto a target surface.

It never creates source geometry.

It never creates solids.

It transforms surface-independent Contours into a surface-aware representation named SurfacePlacement.

---

# 2. Responsibility

The Surface Engine receives Contours and computes how they exist on a target geometric surface.

## Inputs

* Contours
* Placement
* Surface Definition

## Output

* SurfacePlacement

---

# 3. Pipeline Position

The Surface Engine executes immediately after the Provider stage.

```text
Provider

↓

Contours

↓

Surface Engine

↓

SurfacePlacement

↓

Extrusion Engine
```

---

# 4. Public Interface

```python
class SurfaceEngine(ABC):

    @abstractmethod
    def place(
        self,
        contours: list[Contour],
        placement: Placement,
        surface: Surface,
    ) -> SurfacePlacement:
        """
        Adapts and positions contours on a target surface.
        """
```

---

# 5. Contour Input

A Contour represents closed two-dimensional geometry generated by a Provider.

Contours are independent from any target surface.

A Contour does not contain:

* surface references;
* tangent planes;
* projection data;
* three-dimensional placement;
* solid geometry.

The Surface Engine must not mutate the original Contours.

---

# 6. Placement Input

Placement defines the requested position and orientation of the geometry.

A Placement may contain:

* position;
* rotation;
* scale;
* alignment;
* anchor;
* angular position;
* surface coordinates.

Placement contains no geometry.

---

# 7. Surface Input

Surface describes the geometric destination on which the Contours must be adapted.

Initial supported surfaces include:

* Plane;
* Cylinder;
* Cone.

Future surface implementations may include:

* Sphere;
* Torus;
* Mesh;
* NURBS;
* Bézier Surface;
* procedural surfaces.

Providers never depend on a particular Surface implementation.

---

# 8. SurfacePlacement Contract

SurfacePlacement is an independent Kernel contract.

It represents geometry that has already been adapted to a specific surface.

SurfacePlacement is not a modified Contour.

It preserves the distinction between:

* original surface-independent geometry;
* geometry adapted to a target surface.

A SurfacePlacement may contain:

* source Contour references;
* placed or projected Contours;
* target Surface reference;
* local coordinate systems;
* tangent planes;
* surface normals;
* transformation data;
* projection metadata;
* subdivision information;
* approximation tolerance;
* placement metadata.

---

# 9. SurfacePlacement Purpose

SurfacePlacement allows the Kernel to support different placement strategies without changing the Provider API.

Examples include:

* rigid planar placement;
* cylindrical wrapping;
* conical adaptation;
* spherical projection;
* mesh projection;
* UV-based placement;
* conformal mapping;
* segmented approximation.

The Extrusion Engine receives SurfacePlacement without needing to know which Provider created the original Contours.

---

# 10. Surface Adaptation Strategies

The Surface Engine may use different adaptation strategies depending on the target Surface and requested quality.

## 10.1 Rigid Placement

The complete Contour is positioned on one local tangent plane.

This strategy is appropriate for:

* small logos;
* short text;
* small decorations;
* nearly flat regions.

## 10.2 Segmented Placement

The Contour is subdivided into smaller sections.

Each section receives its own local surface orientation.

This strategy is appropriate for:

* larger graphics;
* strongly curved surfaces;
* cylindrical wrapping;
* conical wrapping.

## 10.3 Projected Placement

Contour points or curves are projected directly onto the target Surface.

This strategy is appropriate for:

* spheres;
* meshes;
* NURBS;
* complex organic surfaces.

The selected strategy is an implementation detail of the Surface Engine.

The public API remains unchanged.

---

# 11. Geometry Quality

The SurfacePlacement contract does not define a fixed geometric quality.

Quality depends on Surface Engine parameters such as:

* subdivision density;
* projection tolerance;
* curve approximation tolerance;
* surface sampling resolution;
* maximum angular deviation;
* maximum linear deviation.

These quality settings may be stored as part of Placement, Surface, or SurfacePlacement metadata.

The contract must preserve enough information to evaluate and reproduce the selected placement quality.

---

# 12. Output Rules

The output of the Surface Engine is always SurfacePlacement.

The output remains pre-solid geometry.

No boolean operation has occurred.

No final Model modification has occurred.

The original Contours remain unchanged.

---

# 13. Responsibilities

The Surface Engine shall:

* compute tangent planes;
* compute local coordinate systems;
* compute surface normals;
* orient geometry;
* rotate geometry;
* scale geometry;
* project geometry;
* subdivide geometry when required;
* preserve placement metadata;
* produce SurfacePlacement.

---

# 14. Forbidden Responsibilities

The Surface Engine shall never:

* create source Contours;
* mutate original Contours;
* generate final solids;
* perform boolean operations;
* modify ModelState;
* export geometry;
* depend on a specific Provider implementation.

---

# 15. Surface Independence

Providers never know which Surface will receive their Contours.

The Surface Engine never needs to know which Provider generated the Contours.

The Extrusion Engine receives SurfacePlacement without depending on the original Provider.

This separation is mandatory.

---

# 16. Error Handling

Invalid placement operations shall raise descriptive exceptions.

Examples include:

* unsupported Surface type;
* placement outside valid surface limits;
* invalid local coordinate system;
* projection failure;
* invalid transformation;
* tolerance failure;
* self-intersection caused by projection.

The Surface Engine never terminates the Pipeline directly.

The Pipeline decides how execution failures are handled.

---

# 17. Design Rules

## Rule 1

The Surface Engine owns placement and surface adaptation only.

## Rule 2

The Surface Engine never creates source topology.

## Rule 3

The Surface Engine never creates final solids.

## Rule 4

The Surface Engine never performs boolean operations.

## Rule 5

Original Contours are immutable.

## Rule 6

The output is always SurfacePlacement.

## Rule 7

SurfacePlacement is an independent contract.

## Rule 8

Surface-specific data must not be added directly to Contour.

## Rule 9

Adding a new Surface type must not require changes to existing Providers.

## Rule 10

Placement quality must be configurable and measurable.

---

# 18. Future Extensions

Future versions may introduce:

* adaptive subdivision;
* exact curve-on-surface representations;
* UV mapping;
* geodesic placement;
* conformal mapping;
* mesh wrapping;
* topology-preserving projection;
* manufacturing-aware surface adaptation.

These capabilities must extend SurfacePlacement without changing the Provider contract.

---

# 19. Summary

The Surface Engine transforms surface-independent Contours into an independent SurfacePlacement contract.

This separation preserves the original geometry, retains surface-specific information, and prepares the Kernel to support simple and complex surfaces without redesigning the Provider or Extrusion APIs.
