# DOBO CAD Kernel

# Pipeline API Specification

Version: 2.0

---

# 1. Purpose

This document defines the Pipeline API of the DOBO CAD Kernel.

The Pipeline is responsible for coordinating every Engine of the Kernel.

It is the only subsystem responsible for controlling execution order.

The Pipeline never performs geometry calculations.

---

# 2. Responsibility

The Pipeline transforms a project configuration into a final ModelState by executing the Kernel services in the correct order.

It coordinates execution.

It never owns business logic.

---

# 3. Kernel Pipeline

The canonical execution flow is

```
Application

↓

Configuration

↓

Pipeline

↓

Provider

↓

Contour

↓

Surface Engine

↓

SurfacePlacement

↓

Extrusion Engine

↓

Solid

↓

Boolean Engine

↓

ModelState

↓

Export Engine
```

---

# 4. Public Interface

```python
class Pipeline(ABC):

    @abstractmethod
    def execute(
        self,
        configuration: Configuration,
    ) -> ModelState:
        """
        Executes the complete Kernel pipeline.
        """
```

---

# 5. Inputs

The Pipeline receives a complete project Configuration.

The Pipeline is responsible for creating the ExecutionContext.

---

# 6. Outputs

The Pipeline returns:

• ModelState

Execution statistics remain inside the ExecutionContext.

---

# 7. Execution Context

Every execution owns exactly one ExecutionContext.

ExecutionContext contains runtime information only.

Examples include

• warnings

• errors

• execution time

• executed services

• generated objects

• profiling information

ExecutionContext never contains geometry.

---

# 8. Pipeline Stages

The Pipeline executes the following stages.

## Stage 1

Configuration validation.

---

## Stage 2

Provider execution.

Output

Contour

---

## Stage 3

Surface Engine.

Output

SurfacePlacement

---

## Stage 4

Extrusion Engine.

Output

Solid

---

## Stage 5

Boolean Engine.

Output

Updated ModelState.

---

## Stage 6

Export Engine.

Output

External files.

---

# 9. Execution Rules

Stages execute sequentially.

Every stage receives validated data.

A stage cannot skip previous stages.

Every stage returns immutable output.

---

# 10. Error Handling

The Pipeline owns execution control.

Errors generated by Engines are propagated to the Pipeline.

The Pipeline decides whether execution should

• stop

• continue

• rollback

Future recovery strategies may be added without changing Engine APIs.

---

# 11. Logging

The Pipeline records every executed stage.

Typical information includes

• stage name

• execution time

• warnings

• errors

• generated solids

Logging never modifies geometry.

---

# 12. Dependency Rules

The Pipeline depends on every Engine.

No Engine depends on the Pipeline.

Execution direction is always

Pipeline

↓

Provider

↓

Surface

↓

Extrusion

↓

Boolean

↓

Export

Reverse execution is forbidden.

---

# 13. Parallel Execution

Future implementations may execute independent Providers in parallel.

The Pipeline API remains unchanged.

Parallelism is an implementation detail.

---

# 14. Extensibility

Future stages may be inserted into the Pipeline.

Examples

Simulation

Optimization

Mesh Repair

Manufacturing Analysis

AI Optimization

Additional stages shall preserve the existing API.

---

# 15. Design Rules

Rule 1

The Pipeline owns orchestration only.

Rule 2

The Pipeline never creates geometry.

Rule 3

The Pipeline never performs boolean operations.

Rule 4

The Pipeline owns ExecutionContext.

Rule 5

The Pipeline coordinates every Engine.

Rule 6

Execution order is deterministic.

Rule 7

Engine implementations remain independent from the Pipeline.

---

# 16. Summary

The Pipeline is the central coordinator of the DOBO CAD Kernel.

It guarantees deterministic execution, preserves architectural separation between Engines and provides a stable execution model for every application built on top of the Kernel.
